Abstract

Driving-scene generators each consume their own conditioning. MagicDrive takes a rasterised bird's-eye-view map with projected boxes, DriveDreamer2 a six-view clip with a rendered HD map, UniScene a voxelised occupancy layout. The scene a practitioner already has seldom arrives in any of these forms. We define UniSIR, one scene representation, translate inputs of different types into it — annotations, simulator files, or a sentence — and compile it into each backend's native conditioning through a small adapter. Because the representation is plugged into the interfaces the backends were trained on rather than replacing them, the question we can answer is whether the adapter costs anything, and we answer it by measurement rather than assertion: with only the map channel swapped for MagicDrive's own raster, image quality is statistically indistinguishable from the native conditioning on all six cameras and detection is slightly better. On 6012 frames the compiled dataset is closer to real data than a matched real-vs-real sample is to itself, and closer still at 150 frames per view, so the comparison does not depend on the sample size at which it is made. The occupancy backend takes the representation directly, its native input being the layout we already hold. We also use the representation to construct long-tail scenarios with a traffic simulator — occluded crossings, truck cut-ins, oncoming drift, night squeezes — each checked for clearance before it is rendered. Code, adapters and scenarios are released.

Method

Representation

A document is one frame in a single ego frame (x right, y forward, z up, metres): the ego state and its intended path, actors as oriented boxes with velocity, the map as polylines with a semantic kind, camera intrinsics and extrinsics, and the environment. Every block is paired with a modality mask that records what the input actually supplied, so a document states what it can and cannot fill before anything is compiled: the same type describes a nuScenes annotation, a simulator frame, and a document made from a sentence.

Adaptation

An adapter is a pure function from a document to a backend's payload, with no training and no learned parameters. The map is rasterised into eight binary planes at 0.5 m over ±50 m for MagicDrive; the same document is projected into a six-view clip with a rendered HD-map canvas for DriveDreamer2; and it is voxelised into an 18×200×200 layout over ±40 m for UniScene, whose native slot is that tensor — so for that backend the representation is the input rather than a translation of it.

Verification

Before anything is rendered, every payload is checked against the backend's own capability: shape and range, camera conventions against the backend's loader, and temporal consistency on the rendered frames. A payload either compiles whole or is rejected with the reason, which is what lets us treat the numbers below as a property of the representation rather than of a lucky run.

Results

1. Long-tail scenarios, rendered end to end

Each clip is 20 frames at 4 fps across six views, rendered by the video backend from a single document. None of the scenes exists in the dataset: they are constructed, simulated, checked for clearance, and then rendered.

2. The image backend, on the same documents

Each frame is one document rendered by the image backend; the roads, the actors and the weather come from the document, not from a caption.

3. The occupancy backend

UniScene's native slot is the layout tensor itself, so the document is compiled straight into it.

4. Parity with the native conditioning

Only the map channel differs between the two arms; the frames, the seeds and the evaluators are the same. Image quality is statistically indistinguishable on all six cameras, and detection is slightly better, which is what we mean by the adapter costing nothing measurable.

5. The generated dataset against a real-data ceiling

Both rows are measured through the identical protocol, against a real reference that has been through the same crop-and-reconstruct as the generated frames. On the full 6012 frames the compiled set is closer to real data than a matched real-vs-real sample is to itself, and it stays closer at 150 frames per view, so the result does not depend on the sample size at which it is measured.

6. What each input family can supply

Rows are inputs, not ablations: a zero is a property of the input, not of the adapter. A map alone or a sentence alone renders a plausible frame that contains no detectable actor, which is what the document's modality mask warns about before anything is compiled.
